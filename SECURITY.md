# Security policy

Do not open a public issue containing a vulnerability exploit, credential,
private tenant URL, or customer data.

Use the repository host's private vulnerability-reporting feature. If that
feature is unavailable, open a non-sensitive issue asking a maintainer to
provide a private reporting channel; never include exploit details or secrets
in that issue.

Supported releases are the latest tagged release only. The project is a
learning lab, not a production service. Maintainers will acknowledge a complete
private report, reproduce it with synthetic data, and publish a sanitized fix
and advisory when appropriate.
