# Governance

The project uses a maintainer-led, evidence-based model.

- Maintainers own releases, security responses, and the truthfulness of public claims.
- Material changes are discussed in issues before merge.
- Two-person review is preferred for security and integration boundaries.
- A release requires green verification, a clean secret scan, an SBOM, and reviewed notices.
- Optional vendor integrations must remain replaceable and must not break the local profile.
- No maintainer may publish credentials, tenant data, or third-party binaries without explicit rights.
