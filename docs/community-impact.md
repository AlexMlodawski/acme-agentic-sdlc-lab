# Community impact plan

One repository is evidence of work, not sustained influence. Use the lab as the
center of a repeatable community program.

## Suggested sequence

1. Publish a tagged, reproducible first release.
2. Write a technical article: *Why a feature is not a release decision*.
3. Record a short Baseline → plan → implementation → evidence video.
4. Deliver the lab at an IBM TechXchange or local user-group session.
5. Publish both English and Polish walkthroughs.
6. Answer issues and help other users reproduce the lab.
7. Send structured product feedback to the relevant IBM teams.
8. Publish a follow-up showing what changed because of community feedback.

## Measure impact

- successful quickstart completions;
- distinct users helped;
- external issues and pull requests resolved;
- workshop attendance and completion;
- downstream forks or adaptations;
- concrete product feedback accepted or acted on;
- documentation improvements driven by users.

Do not claim a guaranteed IBM program advancement. Current program decisions
consider sustained expertise, trust, consistency, leadership, and measurable
impact beyond a single artifact.
